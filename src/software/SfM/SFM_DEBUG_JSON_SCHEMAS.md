# SfM Debug JSON Outputs and Schemas

This document summarizes the JSON files emitted by the modified SfM pipeline and the schema of each file.

## Output Location

All files are written to the SfM output directory (`directory_output` / `sOut_directory_`), typically:

- `openmvg/reconstruction_global/`

Some files are produced by `main_SfM.cpp` for any engine, and some are specific to Global SfM.
The file sections below are ordered by when artifacts are generated/written.

## Reconstruction Output Generation Order (Global SfM)

Within `reconstruction_global/`, files are generated in this order:

1. `sfm_debug_matches_loaded.json`
2. `sfm_debug_matches_after_exclusions.json`
3. `relative_rotations_before_rotation_averaging.csv`
4. `camera_rotations_after_rotation_averaging.csv`
5. `sfm_debug_candidate_triplets.json`
6. `sfm_debug_triplet_wise_matches.json`
7. `relative_translations_triplets.csv`
8. `camera_poses_after_translation_averaging.csv`
9. `sfm_debug_tracks_filtered_len3.json`
10. `sfm_debug_structure_after_triangulation.json`
11. `camera_poses_after_ba_T_X.csv`
12. `camera_poses_after_ba_RT_X.csv`
13. `camera_poses_after_ba_KRT_X.csv` (if intrinsic refinement is enabled)
14. `sfm_debug_structure_after_outlier_cleanup.json`
15. `camera_poses_after_ba_final.csv`
16. `sfm_debug_structure_after_final_ba.json`
17. `sfm_data_expanded.json`

## Earlier Pipeline JSON Files (`SfM_GlobalPipeline.py.in`, steps 1-5)

These are JSON files that exist before `openMVG_main_SfM` runs.

### File: `matches/sfm_data.json`

When written:
- Step 1 (`openMVG_main_SfMInit_ImageListing`).

Purpose:
- Initial scene description used by later feature/matching/SfM steps.

Schema (OpenMVG SfM_Data JSON):
```json
{
  "root_path": "/abs/or/rel/path/to/images",
  "views": [
    {
      "key": 0,
      "value": {
        "polymorphic_name": "view",
        "ptr_wrapper": {
          "id": 1,
          "data": {
            "local_path": "",
            "filename": "img_0001.jpg",
            "width": 1920,
            "height": 1080,
            "id_view": 0,
            "id_intrinsic": 0,
            "id_pose": 0
          }
        }
      }
    }
  ],
  "intrinsics": [
    {
      "key": 0,
      "value": {
        "polymorphic_name": "pinhole_radial_k3",
        "ptr_wrapper": {
          "id": 2,
          "data": {
            "width": 1920,
            "height": 1080,
            "focal_length": 1600.0,
            "principal_point": [960.0, 540.0],
            "disto_k3": [0.0, 0.0, 0.0]
          }
        }
      }
    }
  ],
  "extrinsics": [],
  "structure": []
}
```

Field notes:
- `views[*].key`: view ID used in matches.
- `views[*].value...id_intrinsic`: references an intrinsic by key.
- `id_pose` can be undefined or provisional before reconstruction.
- At step 1 this file usually has empty `extrinsics` and `structure`.

### File: `matches/image_describer.json`

When written:
- Step 2 (`openMVG_main_ComputeFeatures`).

Purpose:
- Feature descriptor configuration/metadata used to read features consistently.

Schema:
```json
{
  "describer": "SIFT",
  "preset": "NORMAL",
  "upright": false,
  "num_octaves": 4,
  "contrast_threshold": 0.04,
  "edge_threshold": 10.0
}
```

Field notes:
- Exact keys vary by describer method and OpenMVG version.
- This file defines how feature files are interpreted/loaded.

### File: `matches/excluded_pairs.json` (optional input)

When used:
- Read by `SfM_GlobalPipeline.py.in` before step 6, then passed as `--excluded_pairs_file` into `openMVG_main_SfM`.

Purpose:
- User-provided pair exclusions to remove pairwise matches before reconstruction.

Accepted schema:
```json
{
  "excluded_pairs": [
    {"i": 10, "j": 14},
    [21, 22]
  ]
}
```
or a top-level array of pair entries.

Notes:
- This file is not generated by the pipeline; it is consumed if present.

### File: `matches.e.json` / `matches.putative.json` (not default in this script)

Status in `SfM_GlobalPipeline.py.in`:
- The script writes `.bin` match files by default (`matches.putative.bin`, `matches.e.bin`).
- JSON match exports are not explicitly produced by this script.

If present in your environment:
- They are alternate serialized forms of pairwise match data and can be used for inspection/UI tooling.

## File: `sfm_debug_matches_loaded.json`

When written:
- After matches are loaded in `main_SfM.cpp`.

Purpose:
- Snapshot of pairwise matches immediately after loading from match file(s).

Schema:
```json
{
  "num_pairs": 123,
  "pairs": [
    {
      "i": 10,
      "j": 14,
      "num_matches": 87,
      "matches": [[102, 77], [381, 260]]
    }
  ]
}
```

Field meanings:
- `i`, `j`: view IDs for the image pair.
- `matches`: list of feature-index pairs `[feat_id_in_i, feat_id_in_j]`.

## File: `sfm_debug_matches_after_exclusions.json`

When written:
- After applying `--excluded_pairs_file` logic in `main_SfM.cpp`.

Purpose:
- Pairwise matches after requested pair removals.

Schema:
- Same as `sfm_debug_matches_loaded.json`.

## File: `sfm_debug_candidate_triplets.json`

When written:
- In Global SfM translation stage, immediately after candidate triplet listing (`graph::TripletListing`).

Purpose:
- Raw candidate pose triplets before triplet translation estimation/inlier filtering.

Schema:
```json
{
  "num_triplets": 12345,
  "triplets": [
    {
      "triplet_id": 0,
      "pose_i": 10,
      "pose_j": 14,
      "pose_k": 19
    }
  ]
}
```

Field meanings:
- `triplet_id`: index in the generated candidate triplet array.
- `pose_i`, `pose_j`, `pose_k`: pose IDs forming the candidate triplet.

## File: `sfm_debug_triplet_wise_matches.json`

When written:
- In Global SfM, after triplet-based translation stage generates `tripletWise_matches`.

Purpose:
- Pairwise feature correspondences after triplet-consistency-based filtering/selection.

Schema:
- Same as `sfm_debug_matches_loaded.json`.

## File: `sfm_debug_tracks_filtered_len3.json`

When written:
- In Global SfM initial structure stage, after `tracksBuilder.Filter(3)`.

Purpose:
- Multi-view tracks retained with minimum track length 3.

Schema:
```json
{
  "num_tracks": 456,
  "tracks": [
    {
      "track_id": 0,
      "observations": [
        {"view_id": 10, "feat_id": 102},
        {"view_id": 14, "feat_id": 77},
        {"view_id": 19, "feat_id": 45}
      ]
    }
  ]
}
```

Field meanings:
- `track_id`: internal track identifier.
- `observations`: per-view feature IDs belonging to the track.

## File: `sfm_debug_structure_after_triangulation.json`

When written:
- In Global SfM, immediately after triangulation of initial structure.

Purpose:
- Landmark observation graph after invalid triangulations are removed.

Schema:
```json
{
  "num_landmarks": 321,
  "landmarks": [
    {
      "landmark_id": 12,
      "num_observations": 4,
      "observations": [
        {"view_id": 10, "feat_id": 102},
        {"view_id": 14, "feat_id": 77}
      ]
    }
  ]
}
```

Field meanings:
- `landmark_id`: structure/3D point ID.
- `observations`: feature observations that currently support that landmark.

## File: `sfm_debug_structure_after_outlier_cleanup.json`

When written:
- In Global SfM, after outlier removal and unstable pose/observation cleanup.

Purpose:
- Landmark observation graph after residual/angle filtering and cleanup thresholds.

Schema:
- Same as `sfm_debug_structure_after_triangulation.json`.

## File: `sfm_debug_structure_after_final_ba.json`

When written:
- In Global SfM, after final bundle adjustment.

Purpose:
- Final landmark observation graph used in the exported result.

Schema:
- Same as `sfm_debug_structure_after_triangulation.json`.

## Debug CSV Outputs (Global SfM)

These CSV files are written by the Global SfM pipeline to the reconstruction output directory.

### File: `relative_rotations_before_rotation_averaging.csv`

When written:
- Before global rotation averaging (from relative rotation estimates).

Header:
```csv
pose_i,pose_j,view_i,view_j,image_i,image_j,qw,qx,qy,qz,weight
```

Schema:
- `pose_i`, `pose_j`: pose IDs for the relative edge.
- `view_i`, `view_j`: representative view IDs for those poses (or undefined).
- `image_i`, `image_j`: corresponding image paths.
- `qw,qx,qy,qz`: quaternion for relative rotation `R_ij`.
- `weight`: edge weight/confidence.

### File: `camera_rotations_after_rotation_averaging.csv`

When written:
- After global rotation averaging.

Header:
```csv
pose_id,view_id,image_path,qw,qx,qy,qz
```

Schema:
- `pose_id`: pose ID.
- `view_id`: representative view ID for the pose.
- `image_path`: image path for that representative view.
- `qw,qx,qy,qz`: averaged global rotation quaternion.

### File: `relative_translations_triplets.csv`

When written:
- During translation averaging setup, from triplet-derived relative translations.

Header:
```csv
group_id,view_i,view_j,t_x,t_y,t_z
```

Schema:
- `group_id`: triplet/group index that produced this relative translation.
- `view_i`, `view_j`: view IDs of the relative translation edge.
- `t_x,t_y,t_z`: relative translation vector components.

### File: `camera_poses_after_translation_averaging.csv`

When written:
- After translation averaging (before BA).

Header:
```csv
pose_id,view_id,image_path,cx,cy,cz,qw,qx,qy,qz
```

Schema:
- `pose_id`: pose ID.
- `view_id`: representative view ID.
- `image_path`: representative image path.
- `cx,cy,cz`: camera center in world coordinates.
- `qw,qx,qy,qz`: pose rotation quaternion.

### Files with same pose CSV schema

These files reuse the same header/schema as `camera_poses_after_translation_averaging.csv`:

- `camera_poses_after_ba_T_X.csv`:
  after BA refining translation + structure.
- `camera_poses_after_ba_RT_X.csv`:
  after BA refining rotation + translation + structure.
- `camera_poses_after_ba_KRT_X.csv`:
  after BA refining intrinsics + rotation + translation + structure (when intrinsic refinement is enabled).
- `camera_poses_after_ba_final.csv`:
  final BA output after outlier cleanup.

## File: `sfm_data_expanded.json`

When written:
- Final export stage in `main_SfM.cpp` (alongside `sfm_data.bin`), after all global SfM filtering/BA stages.

Purpose:
- Full final reconstruction in OpenMVG JSON format (`ESfM_Data(ALL)`).

Schema:
```json
{
  "root_path": "...",
  "views": [/* same style as sfm_data.json */],
  "intrinsics": [/* camera models + params */],
  "extrinsics": [
    {
      "key": 0,
      "value": {
        "rotation": [[r00, r01, r02], [r10, r11, r12], [r20, r21, r22]],
        "center": [cx, cy, cz]
      }
    }
  ],
  "structure": [
    {
      "key": 1234,
      "value": {
        "X": [x, y, z],
        "observations": [
          {
            "key": 10,
            "value": {
              "id_feat": 102,
              "x": [u, v]
            }
          }
        ]
      }
    }
  ],
  "control_points": []
}
```

Field notes:
- `extrinsics`: final solved camera poses.
- `structure`: final 3D landmarks and 2D feature observations (`id_feat`).
- `observations[*].key`: view ID; `id_feat`: feature index in that view.

Note:
- This is the full scene representation, not a compact debug-specific schema.

## Stage Mapping Summary

- Loaded matches: `sfm_debug_matches_loaded.json`
- Post-exclusion matches: `sfm_debug_matches_after_exclusions.json`
- Candidate triplets (global): `sfm_debug_candidate_triplets.json`
- Triplet-wise matches (global): `sfm_debug_triplet_wise_matches.json`
- Tracks after min length 3 (global): `sfm_debug_tracks_filtered_len3.json`
- Structure after triangulation (global): `sfm_debug_structure_after_triangulation.json`
- Structure after outlier cleanup (global): `sfm_debug_structure_after_outlier_cleanup.json`
- Structure after final BA (global): `sfm_debug_structure_after_final_ba.json`
- Final full SfM export: `sfm_data_expanded.json`
